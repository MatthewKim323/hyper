Two platforms. Vercel serves `web/studio`; Railway runs everything Python or Node that
needs a long-lived process. The hand tracker needs no host at all.

## Live

| Service | URL |
| --- | --- |
| Frontend | `https://hyper.stephenhung.me` |
| API | `https://api-production-0bd10.up.railway.app` |
| Railway project | `hyper` (6 services) |

## Topology

| Service | Platform | What it is |
| --- | --- | --- |
| `hyper.stephenhung.me` | Vercel | The Next app in `web/studio` |
| `api` | Railway | `backend/Dockerfile`, serves `app.main` |
| `evaluator` | Railway | `backend/evaluator/Dockerfile`, the Jev readiness service |
| `ingestion-worker` | Railway | Same API image, `START_MODULE=app.ingestion_worker` |
| `artifact-worker` | Railway | Same image, `START_MODULE=app.artifact_worker` |
| `counterparty-worker` | Railway | Same image, `START_MODULE=app.counterparty_worker` |
| Postgres | Railway | Managed |

<Warning>
The workers are not optional. Without `ingestion-worker` an uploaded source stays
`index_status='pending'` forever and evidence search never sees it — the upload appears to
succeed and the file is simply never indexed.
</Warning>

## The hand cursor

It does not need hosting. MediaPipe runs entirely in the browser, and its ~30 MB of wasm
and model files live in `web/studio/public/mediapipe`, which is gitignored and rebuilt by
the `postinstall` script Vercel runs on every build. Nothing to deploy, nothing to pay for.

## Frontend

```sh
cd web/studio
vercel link
vercel --prod
```

Set the project's **Root Directory** to `web/studio`. Environment variables:

| Variable | Value |
| --- | --- |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | The key pairing with the backend's `CLERK_ISSUER` |
| `NEXT_PUBLIC_ALWAYS_ONBOARD` | `0`, so completion is remembered |
| `ONBOARDING_BACKEND_URL` | The Railway API URL, for the `/api/onboarding/*` rewrite |
| `NEXT_PUBLIC_ONBOARDING_WS_URL` | `wss://` + the Railway API host |

<Warning>
`NEXT_PUBLIC_ONBOARDING_WS_URL` is required in production. The Next rewrite proxies HTTP
only — it does not proxy WebSockets — so without it the voice socket resolves to the Vercel
domain and never connects. Onboarding then reports that the service is unavailable.
</Warning>

## Backend

```sh
railway init --name hyper
railway add -d postgres
railway add -s api
railway up --service api --ci
```

<Warning>
`railway up` does **not** read the repository's `railway.toml` for a service created this
way: it runs railpack auto-detect, which scans the repo root, finds no single app and
fails. Set the builder on the service itself — the Dockerfile path, healthcheck and
restart policy — through the dashboard or the Railway MCP, then deploy.
</Warning>

The API service uses `backend/Dockerfile` with `/health` as its healthcheck. Add each worker as another service from the same image, setting only
`START_MODULE`; a crashed worker then cannot take the API down.

Environment variables on the API service:

| Variable | Notes |
| --- | --- |
| `DATABASE_URL` | From the Postgres plugin. Required — see below |
| `CLERK_ISSUER` | Your Clerk Frontend API URL |
| `CLERK_AUTHORIZED_PARTIES` | Must include `https://hyper.stephenhung.me` |
| `ALLOWED_ORIGINS` | Must include `https://hyper.stephenhung.me` |
| `DEEPGRAM_API_KEY` | The voice agent's entry point |
| `AI_GATEWAY_API_KEY` | Jev, concern cards, artifacts |
| `EVALUATOR_URL` | The evaluator service's private URL |
| `EVALUATOR_SECRET` | Shared with the evaluator service |
| `APP_ENV` | `production` |

<Note>
`ALLOWED_ORIGINS` is checked separately for WebSockets. An origin missing there closes
every voice socket with code 1008 while ordinary HTTP keeps working, which is hard to
diagnose from the browser.
</Note>

With `APP_ENV=production` or on Railway, a missing `DATABASE_URL` raises at startup
instead of silently falling back to a local SQLite file that looks healthy and holds
nothing.

## Evaluator

Its own service, because it is Node while the API image is Python. Onboarding can never
report ready without it. Set `EVALUATOR_HOST=0.0.0.0` (the Dockerfile already does),
`EVALUATOR_SECRET` to match the API, and `AI_GATEWAY_API_KEY`. Keep it on the private
network: it holds the gateway key and trusts only that shared secret.

## Domain

```sh
vercel domains add hyper.stephenhung.me
vercel alias set <deployment-url> hyper.stephenhung.me
```

Then add the same origin to the backend's `ALLOWED_ORIGINS` and `CLERK_AUTHORIZED_PARTIES`,
and to the authorized origins in the Clerk dashboard.

## Docs

The docs are hosted by Mintlify and reverse-proxied at `/docs` by the Next rewrite in
`web/studio/next.config.ts`.

<Warning>
Do **not** add Mintlify's CNAME for this domain. It sends every path to them, which would
take the product offline. The apex already serves the app; only `/docs` is proxied.
</Warning>

Mintlify's domain validation needs two TXT records, which live on the Vercel-managed zone:

```sh
vercel dns add stephenhung.me _acme-challenge.hyper TXT "<acme token>"
vercel dns add stephenhung.me _cf-custom-hostname.hyper TXT "<hostname id>"
```

The existing CAA on the apex already allows `pki.goog` and `letsencrypt.org`, which covers
the issuers Mintlify's edge uses, so it needs no change. A zone with a stricter CAA would
have to add one before a certificate could be issued.

## Clerk production

The app runs on a development Clerk instance. Those have strict usage limits and are
permissive about origins, so a real deployment wants a production one.

Creating it is interactive and cannot be scripted — the CLI says so itself:

```sh
clerk deploy          # interactive; needs a human terminal
clerk deploy status   # read-only, safe to run anywhere
```

The DNS it needs is already in place, pre-created on the Vercel zone and resolving:

| Record | Target |
| --- | --- |
| `clerk.hyper` | `frontend-api.clerk.services` |
| `accounts.hyper` | `accounts.clerk.services` |
| `clkmail.hyper` | `mail.<id>.clerk.services` |
| `clk._domainkey.hyper` | `dkim1.<id>.clerk.services` |
| `clk2._domainkey.hyper` | `dkim2.<id>.clerk.services` |

After `clerk deploy` completes, the keys change and four places need the new values:

| Where | Variable |
| --- | --- |
| Vercel | `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (now `pk_live_`) |
| Railway `api` | `CLERK_PUBLISHABLE_KEY`, `CLERK_ISSUER` (`https://clerk.hyper.stephenhung.me`) |
| Railway workers | the same two |
| Clerk | `allowed_origins`, via `clerk api -X PATCH /instance` |

<Warning>
Existing development users do not carry over, and the session you are testing with stops
working. Do this when you can sign in again, not minutes before a demo.
</Warning>

## Checks

```sh
curl https://<api-host>/health              # {"status":"ok"}
curl -I https://hyper.stephenhung.me/mediapipe/hand_landmarker.task   # 200, ~7.8 MB
```

Then sign in and confirm the voice orb connects — that exercises Clerk, the WebSocket
origin list, Deepgram and the evaluator in one step.

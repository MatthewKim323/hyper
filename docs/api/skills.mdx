All routes require Clerk authentication and are organization-scoped. The same non-administrative operations are exposed to dashboard agents and Devin workers.

| HTTP | Agent tool | Purpose |
| --- | --- | --- |
| `GET /skills?query=accrual` | `search_learned_skills` | Short summaries of active, current versions. `include_inactive=true` includes drafts/history for inspection. |
| `POST /skills` | `save_learned_skill` | Save an immutable draft with optimistic version check. |
| `GET /skills/{id}` | `get_learned_skill` | Load SKILL.md, resource names, provenance, approval and reported outcome counts. |
| `GET /skills/{id}/resource?path=scripts/calculate.py` | `get_skill_resource` | Load one file, with package integrity check. Never executes code. |
| `POST /skills/execution-evidence` | `save_skill_execution_evidence` | Save execution logs as explicitly agent-reported source evidence. |
| `POST /skills/{id}/runs` | `record_skill_run` | Report passed/failed/needs_input with exact hash and source evidence. |
| `POST /skills/{id}/activate` | Owner only | Activate latest passing evidence after independent review. |
| `POST /skills/{id}/retire` | Owner only | Remove a version from reuse; preserve its record. |

`GET /skills/{id}` also returns `latest_run` (`run_id`, `outcome`, `summary`, `checks`, `duration_ms`, `created_at`, `evidence_current`, `verification`) or null. Activation only accepts the newest report, so this is the one to show an owner for review.

## Draft example

```json
{
  "name": "fixed-rate-service-accrual",
  "description": "Calculate month-end accruals for confirmed fixed-rate services",
  "instructions": "Use the expense accrual API for exact calculations. Verify contract rates, delivery cutoff and complete posted ledger coverage. Escalate blocking issues; never infer posting from approval.",
  "applicability": "Confirmed whole-unit service delivery with approved account mappings in supported currencies.",
  "limitations": "No FX, taxes, capitalization or unconfirmed service. No automatic ledger posting.",
  "source_ids": ["actual-source-id"],
  "research_urls": ["https://agentskills.io/specification"],
  "resources": {
    "references/input-contract.md": "Document the verified input schema here.",
    "tests/test_amount.py": "def test_example():\n    assert 40 * 100000 == 4000000\n"
  },
  "based_on_version": 0
}
```

This is a request-shape example, not a validated skill; a multiplication assertion alone cannot validate an accounting workflow. Supply meaningful executable code/tests, actual accounting research citations and real evidence before activation. Source IDs are checked for current organization ownership. Research URLs are stored as citations, not automatically fetched or verified.

The response contains id, version, package_hash and status=draft. Future revisions use the highest saved version as based_on_version. Exact repeat saves reuse the last version. Resources are text-only, safe relative paths under scripts/references/tests/assets, up to 100 KB each and 500 KB total. SKILL.md is generated by the service rather than supplied as a resource.

## Execution and activation

Execute the package in the authorized worker workspace. Persist logs with `{ "request_key": "task-123-tests", "content": "actual commands, exit codes, assertions and outputs…" }`. Keep secrets out of logs. Then record:

```json
{
  "skill_id": "returned-id",
  "request_key": "task-123-run",
  "package_hash": "returned-hash",
  "outcome": "passed",
  "summary": "Describe the work actually executed and measured results.",
  "evidence_source_ids": ["saved-execution-source-id"],
  "checks": ["Describe independent expected values and actual outputs"],
  "duration_ms": 1000
}
```

This returns a run_id with verification=self_reported. To activate, the owner supplies skill_id, package_hash, run_id and exactly:

`"attestation": "I independently reviewed the tests, accounting assumptions, and evidence for this skill version"`

Activation requires the latest report to pass, current source evidence, package integrity and a tests resource. The previous active version is retired. A subsequent failed run quarantines the version. Stale, draft, retired and quarantined versions can be inspected but must not execute as reusable active procedures. Retire accepts skill_id and reason.

Elasticsearch is an accelerator, not the authority. Activation returns index_status and search returns search_mode; index outages degrade to keyword matching. Skills never confer approval, posting, credential, or external-action permissions. See the plan for validation boundaries.

All routes require a current Clerk session JWT in `Authorization: Bearer ...`. The backend resolves organization membership; requests cannot select another organization. The voice agent receives the same scoped operations.

## Storage

- **Postgres**: organizations, memberships, onboarding sessions, immutable source versions, schema-validated financial records in JSONB, extracted evidence chunks, and durable indexing jobs.
- **Private S3-compatible bucket**: original uploaded bytes. Object keys are generated by the server and never accepted from clients.
- **Elasticsearch**: a rebuildable search index. Keyword retrieval covers every evidence chunk. With `ELASTIC_INFERENCE_ID`, prose documents additionally use `semantic_text` and RRF hybrid search. Structured financial rows remain SQL/BM25 by default; `ELASTIC_SEMANTIC_DATASETS` optionally embeds selected text-rich datasets.

Numbers are validated against NUMERIC(38,12), stored without binary floating-point conversion, and cast to NUMERIC for SQL calculations. Results use decimal strings and preserve original units. SQLite remains available for onboarding/offline tests; numeric aggregates deliberately require Postgres.

## Upload

`POST /sources` accepts multipart form fields:

| Field | Meaning |
| --- | --- |
| `file` | Required original file, max 20 MiB |
| `source_key` | Stable logical source name; defaults to filename |
| `dataset` | Optional financial dataset name. Omit for document search only |
| `currency` | Source currency/asset code, e.g. USD or USDC |
| `field_types` | JSON object mapping columns to text, numeric, or date |
| `id_field` | Primary record identifier column |

Financial imports support CSV, JSON object/array, and JSONL. Documents support TXT, Markdown, JSON, JSONL, CSV, and text PDFs. PDF extraction retains page citations but does not infer accounting tables or perform OCR. Scanned/encrypted PDFs are rejected.

Example browser call:

```javascript
const body = new FormData();
body.append("file", file);
body.append("source_key", "accounting/ap-export");
body.append("dataset", "ap_invoices");
body.append("currency", "USD");
body.append("id_field", "invoice_id");
body.append("field_types", JSON.stringify({
  amount_cents: "numeric",
  date: "date",
  due_date: "date"
}));
const response = await fetch(api + "/sources", {
  method: "POST",
  headers: { Authorization: "Bearer " + await Clerk.session.getToken() },
  body
});
const source = await response.json();
```

Response includes `id`, `version`, `sha256` of the original bytes, `record_count`, `schema`, `active`, `index_status`, and `deduplicated`.

Identical bytes and parsing options under the same organization/source_key return the existing version. Changed content creates a new immutable version and supersedes the earlier source. SQL queries see the new records immediately. Search excludes both superseded sources and versions not fully indexed. Reuploading a historical identical version returns that version with `active: false`; it does not silently restore it.

Overlapping record IDs across other active source keys in one dataset are rejected to prevent double-counting exports. Without an identifier column, row numbers are used; supply a stable `id_field` for datasets split across files. Currency is source-level: split multi-currency files before ingestion. Explicit schemas are recommended; only JSON integer values, *_cents, and conventional date fields are inferred automatically.

## API endpoints

| Endpoint | Purpose |
| --- | --- |
| `GET /sources?limit=50&offset=0` | Paginated source/version metadata |
| `GET /sources/{id}?offset=0&limit=10` | Extracted content with row/page/character citations |
| `GET /sources/{id}/download` | Authenticated original-byte download |
| `GET /sources/{id}/status` | Durable indexing job status and attempt count |
| `POST /sources/{id}/reindex` | Retry/rebuild a non-running source job |
| `GET /datasets` | Available financial dataset schemas, counts, source IDs, currencies |
| `POST /financials/query` | Read rows, filter, group, count, sum, average, minimum, maximum |
| `POST /evidence/search` | Cited keyword/hybrid evidence search |
| `POST /sessions/{id}/archive` | Save/index a versioned transcript snapshot for future conversations |

Transcript history is already persisted automatically in Postgres. The archive endpoint additionally makes a snapshot searchable; call it after onboarding or a conversation ends and again after new messages if desired.

## Financial queries

```json
{
  "dataset": "ap_invoices",
  "operation": "sum",
  "field": "amount_cents",
  "filters": [
    {"field":"due_date","op":"gte","value":"2026-06-01"},
    {"field":"due_date","op":"lte","value":"2026-06-30"}
  ],
  "group_by": ["vendor_id"],
  "limit": 100,
  "offset": 0
}
```

This is the **gross invoice amount**, not outstanding payables: allocations, credits, and payments require separate queries/reconciliation. The tool never invents accounting semantics or silently treats gross as net.

Operations: `rows`, `count`, `sum`, `avg`, `min`, `max`. Filter operators: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`. Maximum 12 filters, 3 grouping columns, 200 results per page; SQL has a 5-second statement timeout. Arbitrary SQL, joins, writes, and arbitrary expressions are not exposed to the model.

Aggregates include currency as an automatic grouping dimension. Null currency means unspecified, not USD. No FX conversion is implied. Values retain imported units, including cents. Null numeric cells are ignored by SQL sums/averages; `record_count` counts all matching rows. Follow `has_more` for grouped or row results; totals are calculated over the entire matching population, not the result page.

## Evidence search

```json
{"query":"termination clause and custody fees","limit":8}
```

Optional `dataset` restricts the search. Response:

```json
{
  "mode":"hybrid",
  "coverage_complete":true,
  "unindexed_sources":0,
  "hits":[
    {"source_id":"src_...","id":"src_...:0","filename":"agreement.pdf",
     "version":1,"locator":"page:2:chars:0-2200","content":"...","score":0.03}
  ]
}
```

Every search branch filters organization and active/ready source IDs. Hits are checked against Postgres again, and returned text comes from the authoritative stored chunk. Search scores measure relevance, not truth. Zero results while `coverage_complete=false` cannot establish that evidence is absent.

An unavailable semantic endpoint produces an indexing/search failure, never a silent downgrade. Unconfigured inference explicitly reports `mode: keyword`.

## Agent tools

Deepgram receives `list_datasets`, `query_financials`, `search_evidence`, and `get_source`, alongside `update_context`. Tool arguments use the same validation as the HTTP endpoints. Organization scope comes from the authenticated session. Retrieval sets the orb to researching, preserves source references for Jev, and is cancelled/discarded on an interrupted turn.

## Failure recovery and boundaries

Uploads save the original, relational records, chunks, and a pending job before returning. A separate worker claims jobs with leases; Postgres SKIP LOCKED permits multiple ingestion workers. After a crash, an expired lease can be reclaimed. Failed jobs retain source data and expose retry status. Repeated indexing overwrites deterministic chunk IDs.

There is no distributed transaction across S3/Postgres/Elasticsearch. An S3 write followed by a database failure may leave an unreferenced private object; it does not become queryable. Partial Elasticsearch writes remain excluded until the entire source is marked ready. Keep originals and database backups; rebuild search from stored chunks.

Uploads are synchronous through parsing/object storage/database commit, with indexing asynchronous. This implementation does not include OCR, arbitrary office formats, live connectors, an accounting reconciliation engine, source deletion/retention jobs, or product frontend upload UI.
